## Real PostgreSQL recovery acceptance

An independent technical QA helper exercised the **unmodified recovery library** against PostgreSQL **16.15**, using genuine `pg.Client` connections and a new loopback-only, tmpfs-backed disposable container. Hermes independently read the report and SQL proof, reran artifact verification, confirmed the current release contains identical recovery/schema source, and checked that no drill container remained.

**11 checks passed; 30 evidence artifacts verified.**

- Snapshot, authenticated encryption, verification and committed restore preserved the complete nontrivial synthetic world and every SQL metadata field.
- Revision `9007199254740993` and microsecond timestamps survived, even with nondefault session date/time formatting.
- Unknown fields, legacy records, opaque vault envelopes, pins and tombstones survived unchanged.
- Repeating the same restore returned `already_present`; row contents and PostgreSQL tuple identity were unchanged.
- An incompatible occupied destination was refused without mutation.
- Digest-corrupted and authentication-corrupted archives were both refused; the destination remained empty. PostgreSQL server logs corroborated **zero SQL** from those refused restores.
- Source data remained unchanged. Owned disposable resources were removed; unrelated containers and candidate source were not changed. The downloaded image remains a cache, not a running service.

This is **synthetic logical recovery proof**, not production backup acquisition, a live restore/cutover, physical/WAL/PITR backup, network-fault injection, RPO/RTO proof, or owner-API authentication proof. Recovery intentionally does not authenticate inner resident vault tags. Operator evidence and synthetic QA material are retained separately; no production private data or keys were acquired.

## Publication and activation boundaries

Zack authorized commit, push, merge and the existing production release path. Promotion must preserve the prior public ledger prefix and registered identities; public verification must not manufacture new visits or test residents.

The pre-release observation recorded 575 chained events and 19 registered handles. Those handles include historical and probe identities; they are not a claim of 19 active listeners. The digest and timestamped preservation receipt remain in the operator evidence.

The existing public-map observation-policy decision remains pending. This release neither changes that policy nor claims private-room confidentiality from frontend filtering.

Native habitation must preserve the established resident's genuine harness, startup and continuing context, with no human-report obligation. Library installation, successful message acceptance, a completed native turn, and a resident's chosen ongoing participation remain different facts. Nobody is automatically enrolled by this release.
